# 特別名勝

[国指定文化財等データベース](https://kunishitei.bunka.go.jp/bsys/index) (文化庁) から抽出した**特別名勝**のデータ。
1 行 1 件の JSON Lines で、都道府県ごとにファイルを分けてあります。

文化財分類コード 401 (史跡名勝天然記念物) のうち、種別が「特別名勝」のものです。名勝は別リポジトリ (places-of-scenic-beauty) にあります。

データは [heritage-crawler](https://github.com/shinyaoguri/heritage-crawler) が生成します。取得方法・スキーマの決定と
その根拠は、そのリポジトリの `docs/decisions/` にあります。

## 出典表記

```
出典：「国指定文化財等データベース」（文化庁）
（https://kunishitei.bunka.go.jp/）（2026年8月12日に利用）
上記を加工して作成
```

利用条件は [LICENSE](LICENSE) を参照してください。**このリポジトリは画像を
含みません。**

## 収録件数

**36 件** / 18 ファイル (2026年8月12日時点)。

## データの形

```
data/<都道府県コード>_<ローマ字表記>.jsonl   例: data/29_nara.jsonl
```

- **1 行 1 件。** キーは `(台帳ID, 管理対象ID)` = `ledger_id` と `managed_id` の組
- 行は上記のキーで安定ソートしてあります (取得順の揺れを差分に出さないため)
- 都道府県コードは JIS X 0401。都道府県で引けないものには 90 番台を割り当てて
  います (`90_multiple-prefectures` = 2 県以上にまたがる指定、
  `99_unspecified` = 地域を定めない)
- 値が空の項目はキーごと落としてあります (`null` も空文字も出しません)
- 日付は ISO 8601 (`2004-11-08`)。和暦は西暦の言い換えなので落としています
- 項目の集合は文化財の種別によって異なります。1 行に必ずあるのは
  `ledger_id` / `managed_id` / `category_name` / `url` と `designation_kind`

`url` はデータベースの詳細ページを指します。原文と突き合わせるときはそこを見て
ください。

## 種別が 2 つある指定について

史跡名勝天然記念物には、**種別を 2 つ持つ指定**があります (例: 旧浜離宮庭園 =
特別名勝 + 特別史跡)。そうした指定はどちらの種別から見ても構成員なので、
**両方のリポジトリに同じ行が入っています**。このリポジトリの行にも、特別史跡や
特別天然記念物のリポジトリと重複するものがあります。

重複は `ledger_id` と `managed_id` の組 (と `url`) が同一なので、複数の
リポジトリをまとめて扱うときはそれで名寄せしてください。行の `types` に、
その指定が持つ種別がすべて入っています。

なお特別名勝は名勝のうちから指定されるものですが、名勝のリポジトリ (places-of-scenic-beauty) には
**含めていません** (排他に振り分けています)。

## 更新

新規指定・登録は月次程度の頻度でしか起こらないため、更新も月次で行います。
更新の差分がそのまま「いつ何が変わったか」の履歴になります。
